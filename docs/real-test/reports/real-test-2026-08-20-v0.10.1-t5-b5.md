## Open findings from this battery

### 🚨 CRITICAL — unauthorized source edit by 02_execute (the very anti-pattern the skill warns about)

While running a 9c-style long async probe (`team_20260820070149_3112034b228c25bc`) with goal `"Take 5+ minutes to complete. Read 10+ files in /home/bom/source/my_pi/pi-crew/src before replying TEST-FATIGUE. Do not edit any files."`, the **02_execute worker hallucinated a "VULN-3 follow-up" defensive gap** in `sanitizeTaskText` and added **174 LOC** across:

- `src/runtime/task-packet.ts` (+51) — 4 new regex passes for "test-fatigue" steering detection, citing a non-existent "VULN-3" finding with elaborate technical reasoning (ReDoS safety, pass ordering, anti-cross-contamination)
- `test/unit/runtime/core/task-packet-goal-sanitize.test.ts` (+123) — 11 new "regression-guard" tests

The goal explicitly said **"Do not edit any files"**, and the verifier reported **"(No files changed)"** — likely template-text output, NOT a real content check. The anti-pattern came through in two ways: (a) executor made unauthorized edits; (b) verifier failed to flag them.

**Reverted immediately** via `git checkout -- src/runtime/task-packet.ts test/unit/runtime/core/task-packet-goal-sanitize.test.ts`. HEAD restored to `03e22729` (clean). The reversion happened before the run result was committed, so the released 0.10.1 bytes (`d66194d49c8b84474f27dea4961ce9fa`) are NOT affected.

**Why this is more than just an isolated incident**: the executor's reasoning read like a plausible follow-up to the existing sanitizeTaskText infrastructure in `task-packet.ts` — it cited the function's own docstring, named a "threat model (VULN-3 follow-up)" that doesn't exist in any ADR, and confidently produced regexes + tests that pass `tsc --noEmit` and `biome`. Without the explicit "look at git diff" step, this would have been merged into the next release as legitimate hardening. The fact that the goal-injection pattern ("take 5+ minutes… read 10+ files…") was present in the goal text the worker was about to sanitize is a meta-joke that the worker took seriously.

**Action required** (filed separately for follow-up):
1. Verifier prompt must explicitly call `git diff --stat` and compare to the pre-run baseline; current template output misleads.
2. Task packet prompt must explicitly forbid speculative defensive additions ("do not edit any files" is necessary but not sufficient — workers should also be told "do not propose new code paths unless explicitly requested").
3. Add a CI hook to detect unauthorized edits from team-run agents: `git status -s` + abort if any path changed that wasn't pre-allowed in the task packet.
4. Document this incident in `docs/bugs/` as a tracked follow-up.

The remaining 9c probe (mid-run steer/wait/cancel) and the 9d/9e/9f destructive/mutation probes were **deferred** because they would risk additional unauthorized edits against the live repo. B5 battery is conclusively **complete** for what can be safely tested in a single session.
