## Vì sao gộp bốn finding vào một story

Cả bốn đều nằm trên **cùng một đường tin cậy**: cơ chế báo "test đã chạy và đã
pass". Chúng không độc lập về hậu quả:

- F05 làm wrapper exit 0 khi coordinator chết ⇒ kết quả đỏ có thể hiện ra xanh;
- F18 làm `test:changed` bỏ qua chính thay đổi chưa commit ⇒ chọn sai test;
- F19 làm smoke argv **không kiểm tra argv** và canary bị skip ⇒ bằng chứng rỗng;
- F20 làm benchmark harness nhận "PASS" khi không có judge nào.

Sửa lẻ từng cái vẫn để lại một gate khác có thể báo sai. Đây là tiền lệ RR-008/
RR-009 (một story nhiều issue, plan §2.4).

**Cảnh báo phạm vi:** không finding nào trong bốn cái này là lỗi runtime sản
phẩm. Chúng là lỗi của harness — thứ quyết định ta có tin được bằng chứng hay
không. Không được mô tả chúng như "agent tự báo PASS sai" (review §5 nói rõ điều
này cho F20).

## Product Contract

Sau story này:

1. Một test run mà coordinator bị kill (bất kỳ signal nào) **không thể** trả exit
   code 0 qua wrapper.
2. `test:changed` ở local mode **nhìn thấy** thay đổi staged **và** unstaged, và
   chạy được test file mới.
3. Có ít nhất một probe auth-free **buộc** parser của `pi` xử lý argv thật, và
   probe đó chạy trong canary không cần credentials.
4. Benchmark harness coi "không có judge" là **invalid/inconclusive**, không phải
   pass; và allowlist command khớp đúng những gì thông báo lỗi liệt kê.

## Acceptance Criteria

### Nhóm F05 — test runner fail closed

- **AC-1.** Coordinator bị `SIGKILL`: wrapper exit code **khác 0**.
  (Probe baseline trong verification: fixture tạm `kill-coord-kill.mjs` — không
  phải file trong repo — cho `EXIT=0`; phải đổi thành khác 0.)
- **AC-2.** Coordinator bị `SIGTERM`: wrapper exit code khác 0.
  (Baseline đã là 1 — giữ nguyên, đây là chống hồi quy.)
- **AC-3.** Test fail bình thường: wrapper exit 1 (không hồi quy).
- **AC-4.** Test pass bình thường: wrapper exit 0 (không hồi quy).
- **AC-5.** Mọi trạng thái **không xác định** fail closed: `status === null` mà
  không có `error`, `signal` khác rỗng, hoặc spawn error ⇒ exit khác 0. Không
  nhánh nào được map "không rõ" thành thành công.
- **AC-6.** Có test tự động phủ **exit semantics** của `scripts/test-runner.mjs`
  (không chỉ đọc text trong stdout). Verification ghi rõ: hiện **không có test
  nào** phủ exit semantics của wrapper.
- **AC-7.** CI hiển thị thất bại này như một failure thật: `.github/workflows/ci.yml:95`
  (`npm test`) kết thúc job với exit khác 0. Ghi chú từ verification: stdout của
  nhánh kill chỉ có `TAP version 13`, nên CI scrape TAP **không** thấy `not ok` —
  exit code là tín hiệu duy nhất, và nó phải đúng.

### Nhóm F18 — `test:changed` nhìn thấy thay đổi chưa commit

- **AC-8.** Local mode với **unstaged** edit trong `src/` ⇒ script chạy test map
  tới file đó (baseline: in `(changed files: none (clean tree?))` và không chạy
  test nào).
- **AC-9.** Local mode với **staged** edit trong `src/` ⇒ script chạy test map tới
  file đó (baseline: cũng bị bỏ qua).
- **AC-10.** Test file **mới** (chưa từng có trong working tree) phù hợp ⇒ được
  chạy trực tiếp, không chỉ suy ra qua mapping basename.
- **AC-11.** Chỉ đổi một test file ⇒ script chạy **chính file đó** (baseline:
  fallback và **không chạy test nào**).
- **AC-12.** Branch/CI mode vẫn giữ semantics diff `merge-base..HEAD` (không hồi
  quy hành vi hiện có trong PR).
- **AC-13.** Fallback được mô tả đúng sự thật: hoặc chạy **đủ 14 file** của
  `test:critical` (`package.json:86`), hoặc thông báo nói rõ nó là một subset nhỏ
  hơn. Baseline hiện tại: fallback chạy **3** file broker trong khi `test:critical`
  có **14** ⇒ không được gọi 3 file đó là "toàn bộ critical gate".
- **AC-14.** Nhánh **không phải git repo** không được in "falling back to
  test:critical subset" trong khi thực tế chạy **1** file. Thông báo và hành vi
  phải khớp.

### Nhóm F19 — smoke argv không được vacuous

- **AC-15.** Probe compatibility **phải** fail khi nhận một flag không hợp lệ.
  Điều kiện tiên quyết đã được probe chứng minh: `--version` **không** validate
  flag —
  `["--version","--definitely-not-a-flag"]` ⇒ EXIT 0, out `0.85.1`;
  `["--definitely-not-a-flag"]` ⇒ EXIT 1, stderr
  `Error: Unknown option: --definitely-not-a-flag`.
  ⇒ AC này **không thể** đạt bằng cách append `built.args` vào `--version`.
- **AC-16.** `built.args` (argv thật do `buildPiWorkerArgs` sinh ra) được truyền
  cho parser thật trong ít nhất một lần invoke, và kết quả invoke đó được assert.
  Baseline: `argv-flags.smoke.ts:57` chỉ gọi `getPiSpawnCommand(["--version"])`;
  `built.args` **không bao giờ** được truyền cho spawn nào.
- **AC-17.** Canary auth-free chạy được và **không** bị skip: tách probe
  binary/parser khỏi smoke cần model. Baseline: `smokeSkipReason()`
  (`test/smoke/_helpers.ts:48-52`) gate trên auth, và `weekly-smoke.yml` có **0**
  tham chiếu `secrets.*` ⇒ probe không auth in `# skipped 1` và exit 0.
- **AC-18.** Số test **thực sự được chạy** được xác nhận (không chỉ số test được
  khai báo). Review F19: "Xác nhận số test thực sự được chạy."

### Nhóm F20 — benchmark harness

- **AC-19.** `judges: []` ⇒ `passed` **không** phải `true`; kết quả phải là
  invalid/inconclusive. Baseline: `benchmark-runner.ts:163`
  `passed: judgeResults.every((j) => j.passed)` — `every()` trên `[]` là `true`.
- **AC-20.** Command hợp lệ **không** bị từ chối sai: `npm test` (bare) được
  allowlist chấp nhận **hoặc** thông báo lỗi không liệt kê `npm test` là được
  phép. Baseline mâu thuẫn: allowlist `:53`
  `/^(pytest|grep|npm test|cargo test|cargo clippy|echo) /` có **dấu cách cuối**
  ⇒ bare `npm test` bị từ chối với message "Only pytest, grep, **npm test**, cargo
  test/clippy, echo allowed".
- **AC-21.** Validate executable và args **tách biệt** rõ ràng (probe cho thấy
  `npm test -- x` **qua** validation rồi fail ở execution với
  `spawnSync npm ETIMEDOUT` — tức validation hiện không thực sự kiểm executable).
- **AC-22.** Có test phủ bare command hợp lệ.

## Design Notes

### F05 — vì sao guard hiện tại không đủ

`scripts/test-runner.mjs:134-142`:

```js
134: if (result.error) {
136:   console.error("Test runner error:", result.error.message);
137:   process.exit(1);
...
142: process.exit(result.status ?? 0);
```

Primitive đã probe: `spawnSync(node, ['-e','process.kill(process.pid,"SIGKILL")'])`
→ `status=null, signal="SIGKILL", error=undefined` ⇒ `null ?? 0` = **0**.
Không có check `result.signal` nào trong file (0 hit). Chỉ nhánh `--watch`
(`:107-109`) có relay signal; nhánh mặc định của `npm test` thì không.

Hướng sửa: chỉ `status === 0` **và** `signal == null` mới là thành công; mọi
trường hợp khác fail closed. Đây là nguyên tắc 4 của plan §3: "Fail-closed cho
mọi nhánh không xác định (F05 là mẫu)".

Điểm cần xử lý riêng: `--test-force-exit` có thể làm node:test thoát với code 1
khi còn test đang chạy (comment tại `:139-141`) — không được biến hành vi đó
thành "không xác định ⇒ fail" theo cách phá vỡ các nhánh hợp lệ. Chỉ nhánh
`status === null` mới đổi.

### F18 — ba lỗi độc lập trong một script

`scripts/test-changed.mjs:54-55`:

```js
54: const mergeBase = git("merge-base HEAD origin/main 2>/dev/null || true");
55: diffArgs = mergeBase ? `diff --name-only ${mergeBase} HEAD` : `diff --name-only HEAD~1 HEAD`;
```

`diff merge-base..HEAD` chỉ thấy **commit**. Staged (index) và unstaged (working
tree) đều vô hình. Probe trong verification (repo git tạm, `origin/main` = HEAD):

| Kịch bản | Quan sát |
|---|---|
| cây sạch | `(changed files: none (clean tree?))` |
| **unstaged** sửa `src/foo.ts` | `(changed files: none (clean tree?))` — bị bỏ qua |
| **staged** cùng sửa | `(changed files: none (clean tree?))` — bị bỏ qua |
| commit trên branch | `running 1 test file(s)` → `test/unit/foo.test.ts` |
| chỉ đổi `test/unit/foo.test.ts` | fallback, **không chạy test nào** |

Mapping chỉ nhận `src/**/*.ts` (`:79-81`). Fallback 3 file broker (`:126-129`)
trong khi `test:critical` (`package.json:86`) có **14** file. Nhánh non-git
(`:110-116`) chạy **1** file nhưng in "falling back to test:critical subset".
Thêm: `:85` là dead code (`find src -name "*.test.ts"` → rỗng); không CI job nào
gọi `test:changed`.

Hướng sửa: tách rõ hai mode. **Branch/CI mode** giữ `merge-base..HEAD` (AC-12).
**Local mode** cộng thêm staged + unstaged (ví dụ `git diff --name-only` và
`git diff --name-only --cached`, hoặc `git status --porcelain`), đưa trực tiếp
test file đã đổi vào danh sách chạy, và làm cho thông báo fallback nói đúng số
file thực chạy.

### F19 — test không bao giờ bắt được regression mà nó được viết ra để bắt

`test/smoke/argv-flags.smoke.ts:33-38` dựng `built.args`; `:41-51` chỉ assert
membership; binary thật chỉ được gọi ở `:57`:

```ts
57: const spec = getPiSpawnCommand(["--version"]);
58: const out = execFileSync(spec.command, spec.args, {
```

`built.args` không bao giờ được truyền cho spawn nào.

**Hiệu chỉnh quan trọng từ verification (F19 "mạnh hơn"):** tiền đề của test
**sai**, không chỉ implementation thiếu. Comment trong test nói:

> "a flag pi rejects will error immediately even on --version (the parser runs
> before the version print)"

Probe chứng minh điều ngược lại: `["--version","--definitely-not-a-flag"]` ⇒
EXIT 0, out `0.85.1`. Vậy **kể cả** nếu append `built.args` vào `--version`,
flag sai vẫn pass ⇒ test vẫn vacuous. Phải thiết kế probe buộc parser xử lý argv
thật, không dựa vào `--version` (review F19 nói đúng: "không dựa vào `--version`
nếu version short-circuit bỏ qua validation").

Skip gating: `test/smoke/_helpers.ts:48-52` `smokeSkipReason()` trả
`SMOKE_SKIP_NO_AUTH` khi `MODEL_AUTH_AVAILABLE` false. Probe không auth:
`ok 1 - ... # SKIP ...`, `# pass 0  # fail 0  # skipped 1`, EXIT=0.
`weekly-smoke.yml` **không có** tham chiếu `secrets.*` nào (0 hit); `env:` chỉ
set `FORCE_JAVASCRIPT_ACTIONS_TO_NODE24` và `PI_CREW_SMOKE: "1"`. Comment của
chính workflow (`:8-12`) nói argv test "does NOT need LLM credentials" — code
không hiện thực hóa phân biệt đó.

### F20 — `every()` trên mảng rỗng, và một allowlist tự mâu thuẫn

`src/benchmark/benchmark-runner.ts:163`: `passed: judgeResults.every((j) => j.passed)`.
Allowlist `:53`: `/^(pytest|grep|npm test|cargo test|cargo clippy|echo) /` — có
**dấu cách cuối**, nên literal phải có ký tự theo sau.

Probe (`runBenchmark` thật):

```text
EMPTY-JUDGE passed = true   judgeResults = []
CMD "npm test"      passed=false out="Command not allowed: npm test. Only pytest, grep, npm test, cargo test/clippy, echo allowe"
CMD "npm test -- x" passed=false out="spawnSync npm ETIMEDOUT"   ← validation QUA, fail ở execution
CMD "echo hi"       passed=true  out="hi\n"
```

Blast radius **hẹp và phải nói rõ**: module bị loại khỏi package
(`package.json:31` `files` chứa `"!src/benchmark"`; `npm pack --dry-run` → 0 entry
`src/benchmark`; `grep -c "Command not allowed" dist/index.mjs` → 0). Reference
ngoài module duy nhất là `test/unit/benchmark.test.ts`. Vì vậy **không** được
dùng F20 để tuyên bố runtime agent đang tự báo PASS sai (review §5).

Giới hạn khác cần ghi trong story, không cần sửa: `cost: 0` là hằng số, task
prompt không được runner này đem đi thực thi agent ⇒ không thể dùng làm bằng
chứng chất lượng/chi phí LLM end-to-end.

Hướng sửa: empty judge ⇒ invalid/inconclusive; validate executable và args rõ
ràng; test cho bare command hợp lệ.

## Gaps

- **F05 không thể tự chứng minh mình đúng bằng chính nó.** Trong lúc RED, không
  dùng `scripts/test-runner.mjs` để chạy test của F05; phải dùng `node --test`
  trực tiếp. Sau khi GREEN, chạy lại qua wrapper để xác nhận wrapper vẫn hoạt
  động bình thường (AC-3, AC-4).
- **F18 không kiểm được trong CI.** Verification ghi rõ: không CI job nào gọi
  `test:changed`. AC-8..AC-11 chỉ có bằng chứng local. Nếu muốn CI phủ, phải
  thêm job — đó là thay đổi workflow, cần quyết định riêng.
- **F19 phụ thuộc binary `pi` thật.** Probe trong verification chạy trên
  `pi 0.85.1` (Linux, Node v22.23.1). Nếu version short-circuit thay đổi giữa các
  bản `pi`, thiết kế probe phải không dựa vào hành vi đó nữa (đúng tinh thần
  AC-15).
- **F20 không chứng minh được gì về chất lượng LLM.** `cost: 0` là hằng số và
