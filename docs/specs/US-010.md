# US-010 — Replace sleepSync busy-wait with proper async

## Status

planned

## Lane / Priority

tiny · P3

## Source

- `docs/stories/backlog.md` — Performance epic, US-010 (planned).

## Problem

`sleepSync` (busy-wait `Atomics.wait`/`Date.now()` loop) is used for bounded
retry waits:
- `src/state/coordination/locks.ts` — 10 references (lock acquisition retry)
- `src/state/event-log/sequence-cache.ts` — 8 references
- `src/state/stores/active-run-registry.ts` — 2 references
- `src/state/coordination/mailbox.ts` — 1 reference

A busy-wait pins a core while waiting and makes latency floor = wait
granularity; under contention (concurrent workers) these piles up.

## Goals / Non-goals

- Replace busy-wait retry loops with an async sleep that yields
  (`await new Promise(r => setTimeout(r, ms))`) in the paths that are already
  async-capable.
- KEEP busy-wait in the strictly-sync paths (lock acquisition that must
  return synchronously). If a path cannot be async, leave it and document.
- NOT in scope: changing lock semantics, retry counts, or timeouts.

## Design

Audit each `sleepSync` site; categorize:

1. **Async-callable** — the enclosing function is already `async` or its
   callers are: swap to `await`-based sleep. This is the common case for
   lock retry inside `withRunLock*` async variants and mailbox/registry
   refresh.
2. **Sync-locked** (e.g. `withRunLockSync`): keep busy-wait, but add a
   comment marking it intentional + the reason.

Where a shared helper already exists (`sleepSync` helper — find its
definition), add a sibling `sleepAsync(ms)` and migrate call sites.

## Acceptance Criteria

1. Every async-callable `sleepSync` site now uses `sleepAsync`.
2. Sync paths keep busy-wait with a "sync-locked, intentional" comment.
3. No observable behavior change: same retry counts, same timeouts; all
   existing lock/sequence/mailbox/registry tests stay green.
4. A microbenchmark or test asserts the async path does not pin the event
   loop during the wait (e.g. a timer fires during the wait).

## Validation

| Unit | existing lock/sequence/registry/mailbox suites | 0 fail |
