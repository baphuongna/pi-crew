## Problem

A benchmark judge command containing a QUOTED argument
(e.g. `llm-judge --prompt "score 1-10"`) is split incorrectly — the quotes
are not honored, so the arg becomes `"score` + `1-10"`. Today's fixtures do
not use quotes (so it is latent), but the API shape invites it and the
failure mode is silent (wrong argv to a real process).

## Goals / Non-goals

- Honor simple POSIX-style quoting in the judge command: single quotes,
  double quotes, and backslash escapes.
- Preserve the existing SECURITY posture: the metacharacter blocker must
  still reject shell metacharacters (`;`, `|`, `&`, `$`, backticks, `>`,
  `<`) — quoting support must NOT become a shell-injection vector (we exec
  via argv, never via a shell, so the blocker remains a defense-in-depth
  check on the input shape).
- NOT in scope: full shell grammar (no globbing, no env expansion, no
  command substitution).

## Design

Replace the naive split with a small tokenizer:

```ts
function tokenizeCommand(cmd: string): string[] {
  // state machine: plain | inSingle | inDouble
  // backslash escapes any next char outside single quotes
  // unterminated quote => throw (fail closed, not silently mis-split)
}
```

Then keep the existing metacharacter validation applied to the RESULTING
tokens (arg-level), so `--prompt "a;rm -rf"` still fails the blocker on the
token containing `;`.

## Acceptance Criteria

1. `cmd "a b" c` → `["cmd", "a b", "c"]`.
2. `cmd 'a b'` → `["cmd", "a b"]`.
3. `cmd a\ b` → `["cmd", "a b"]`.
4. Unterminated quote → throws a clear error (no silent mis-parse).
5. Metacharacter blocker still rejects the same inputs as before (test the
   exact set from the current blocker).
6. All existing benchmark tests green.
