# RM-04 — F05 smoke "mutation-verified": reproduce the mutation

## Status

planned

## Lane / Priority

tiny · P3 (verification debt)

## Source

- `docs/stories/backlog.md` — "Deferred — review-round 2026-09-17":
  "F05 smoke 'mutation-verified': reviewer chỉ đọc pattern, chưa tái tạo
  mutation — verify khi chạy smoke tuần tới".

## Problem

During the RR wave, finding F05's test was marked "mutation-verified", but
the reviewer only READ the test pattern — the mutation was never actually
applied. A "mutation-verified" claim that was never reproduced is exactly the
failure mode this project's test discipline (mandatory mutation testing)
exists to prevent. It is a claim-integrity issue, not a code bug.

## Goal

Close the verification debt: actually apply the revert-mutation to the F05
fix and confirm the test goes RED, then restore and confirm GREEN. Record
the evidence (commands + observed output) in `docs/TEST_MATRIX.md` next to
the F05 row.

## Design

1. Locate F05's fix + its test (search `docs/TEST_MATRIX.md` for the F05
   row and the referenced commit/test file).
2. Revert the specific fix hunk (not the whole file) in a scratch copy.
3. Run the test → record RED output (exact assertion message).
4. Restore → run again → record GREEN.
5. Update the TEST_MATRIX row from "mutation-verified (read-only)" to
   "mutation-verified (reproduced; RED→GREEN recorded)" with the observed
   message.

## Acceptance Criteria

1. RED output captured with the failing assertion text.
2. GREEN after restore; full file green.
3. TEST_MATRIX row updated with the evidence (date + observed message).
4. Working tree clean at the end (mutations reverted — verify with
   `git status`).

## Validation

| Layer | Check | Expected |
|-------|-------|----------|
| Mutation | apply revert hunk | test RED, message recorded |
| Restore | revert the revert | test GREEN |
| Docs | TEST_MATRIX row | evidence attached |

## Notes

- If the mutation does NOT go red, that is a real finding (the test is
  vacuous) — escalate to a fix, do not silently mark verified. The session
  norm (SKILL.md anti-pattern section) documents a vacuous test previously
  exposed by exactly this exercise.
