## Source

- This session's assessment: token/run (~22k for a 3-worker fast-fix;
  ~6.6–7.6k tokens per worker) has NOT been optimized; DP-04 attacks the
  small-goal case, this attacks per-worker cost.
- Prompt construction anchors: `src/prompt/prompt-builder.ts`,
  `src/runtime/task-runner/prompt-builder.ts`, model routing context
  (`docs/skills/model-routing-context` describes the pipeline).

## Problem

Each worker's prompt carries a large fixed preamble: role instructions, agent
definition (agents/*.md), skills index, project context, tool docs, plus the
task. Measured ≈6.6–7.6k tokens for simple workers. Only a fraction is task-
specific. Since tokens are the dominant per-run cost (money + latency), a
30% reduction is the single largest efficiency lever available.

## Goals / Non-goals

- Measure first: instrument the actual prompt token breakdown per worker
  (role / agent-definition / skills / project-context / task). Publish the
  breakdown as the spec's baseline evidence — no guessing.
- Then cut the biggest contributors by removing redundancy — e.g. skills
  index entries for skills never invoked, duplicated project context in
  both the preamble and the task packet, verbose tool docs.
- Hard constraint: quality non-regression. This is the "does it still work
  as well" axis — a cheaper prompt that makes workers dumber is a LOSS. Gate
  on an outcome comparison, not just token count.
- NOT in scope: model downgrade (routing ≠ prompt), context compaction
  (already exists), removing safety/role instructions.

## Design

Phase 1 — measurement (no behavior change):

1. Add a debug/instrumented path that reports per-section token estimates of
   the final worker prompt (cheap char/4 or a real tokenizer if one is
   already available in-tree; prefer in-tree).
2. Run the standard fast-fix + implementation smoke; record the breakdown.

Phase 2 — targeted cuts (each independently measurable):

- Deduplicate project context (`.crew/knowledge.md` excerpt injected once).
- Skills: inject only skills relevant to the role/agent (the role already
  declares skills — use that), not the whole index.
- Agent definition: trim boilerplate that repeats the role line.
- Tool docs: keep, they prevent errors (measure before cutting).

Phase 3 — validate:

1. Token delta per worker (target ≥ −30% on the fixed preamble).
2. Outcome non-regression: same smoke tasks produce equally good results
   (green gates, correct files touched) in ≥2 runs.
3. Live tier (real-test skill): a real run must be inspected, not just unit.

## Acceptance Criteria

1. Published token breakdown (baseline) with the instrumented command.
2. ≥30% reduction in the fixed preamble, with the composition recorded.
3. Quality gate: the same 2 smoke tasks still succeed, and a human reads one
   worker's full prompt to confirm nothing load-bearing was dropped.
4. Config escape: a flag to restore the verbose prompt (rollback path).
5. No behavioral change to routing/model selection.
