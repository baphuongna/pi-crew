# DP-04 — fast-fix auto-suggest singleAgent routing

## Status

planned

## Lane / Priority

normal · P2 (direct token/cost win on the most common small tasks)

## Source

- `docs/stories/backlog.md` — "Deferred — performance deep-dive 2026-09-18".
- Measured: a trivial goal through the default team consumes **7.6–9k tokens**
  just for the 3 context-setup steps, because `default` workflow always runs
  assess→execute→verify. The engine ALREADY supports
  `singleAgent: true` (used by the `singleAgent` plan path); the gap is
  routing — nothing suggests it for small goals.

## Problem

Default routing does not consider goal size. Trivial goals (rename a symbol,
fix one line, run one test) pay for full multi-agent orchestration: extra
child processes, extra context, extra wall-clock. The plan/execute engine
already has a cheaper path; it is simply not selected automatically.

## Goals / Non-goals

- Add a **hint / auto-suggest** (not a silent hard switch): when the goal is
  small (heuristic: short goal text AND/OR a trivial-workflow signal),
  return a plan that either uses `singleAgent: true` or a 2-step chain, and
  surface WHY in the plan output.
- Configurable: `routing.smallGoalSingleAgent: "off" | "suggest" | "auto"`
  (default `"suggest"` — visible nudge, user/agent decides).
- NOT in scope: changing the default team/workflow definitions themselves;
  ML-based goal classification.

## Design

Anchors: the planner/assess step that decides fanout —
`src/runtime/team-runner.ts` (`executeTeamRun` → assess), the workflow
resolver (`src/workflows/discover-workflows.ts` + the builtin `default`
workflow), and the existing `singleAgent` support (search for
`singleAgent` in the plan path; `team action=plan` with
`singleAgent: true` produces a sequential single-agent plan).

Heuristic (deliberately simple + explainable):

- `goalTokenCount <= SMALL_GOAL_TOKENS` (e.g. 40) AND no explicit
  `team`/`workflow` override supplied by the caller → suggest.
- Emit in the plan result: `routingHint: { suggested: "singleAgent",
  reason: "goal is small (N tokens); 3-agent setup ≈ 8k tokens overhead",
  estimatedSavings: "~5-6k tokens" }`.
- `"auto"` mode actually switches the workflow; `"suggest"` only annotates.

## Acceptance Criteria

1. `"off"` → no hint, behavior unchanged (regression-safe default escape).
2. `"suggest"` (default) → hint present for small goals, absent for large
   ones; the executed plan is unchanged (annotate only).
3. `"auto"` → the executed plan uses singleAgent/2-step for small goals, and
   the run records the routing decision in the manifest/events (so the cost
   saving is auditable).
4. Hint respects explicit user overrides (never second-guess an explicit
   `team`/`workflow`).
5. Measured: a benchmark goal shows the expected token reduction in `auto`
   mode (record before/after; expect ≈ −5–6k tokens on the trivial case).

## Validation

| Layer | Test | Expected |
|-------|------|----------|
| Unit | `test/unit/runtime/routing-small-goal.test.ts` (new) | off/suggest/auto matrix; override respected; hint text |
| Live | one real `run` on a trivial goal in `auto` mode | fewer workers, lower tokens, run completes |
| Mutation | ignore the override | RED |
| Gates | `npm run test:critical` · `npm run typecheck` · biome | green |

## Notes

- Prefer `"suggest"` as the default: silent routing changes are exactly the
  class of behavior this project has been burned by (see the auto-boomerang
  aliasing trap documented in the real-test skill). Make it visible.
- Pairs with SR-02 (prompt diet) — both attack tokens/run, different levers.
