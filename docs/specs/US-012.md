# US-012 — Cache available models across runs

## Status

planned

## Lane / Priority

normal · P3

## Source

- `docs/stories/backlog.md` — Performance epic, US-012 (planned).

## Problem

The model registry/catalog is rebuilt per resolve:
- `src/runtime/model/model-resolver.ts:30` `resolveModel(input, registry)`
  takes a registry argument.
- `src/runtime/model/model-fallback.ts:682` derives `registryModels` via
  `availableModelInfosFromRegistry(input.modelRegistry)` — registry
  assembled per model resolution/worker spawn.
- Spawning N workers in a team = N registry builds (provider extensions,
  quota data — see `src/runtime/model/provider-quota.ts`).

Registry build is pure configuration-derived data (invariant per
config+env), so caching it is safe.

## Goals / Non-goals

- Cache the registry-derived model info per (config signature, env) with a
  short TTL, shared across workers in a session.
- Invalidate on config changes (same signaling used for config reload).
- NOT in scope: touching `resolveModel` semantics; pre-warming the provider
  (provider-quota freshness is a runtime concern — keep).

## Design

Anchor: where the session's model registry is built
(`src/runtime/model/` session-model / model-budget-summary path; find the
single construction point, likely `model-registry.ts` or in
`session-model.ts:180` rebuild path).

Proposal:

1. Add `availableModelRegistryCache` — key = hash of the authoritative
   config+env inputs (fold hash of `PI_` model env vars + config.model
   section), value = `{ registryModels, expiresAt }`.
2. TTL e.g. 30 s (short enough for config edits mid-session, long enough to
   absorb a 4-way team spawn).
3. `availableModelInfosFromRegistry` or its caller consults the cache
   first; on miss, builds + stores.
4. Expose `__test__registryCacheSize/clear` for unit tests (repo pattern).

## Acceptance Criteria

1. Two consecutive worker spawns with unchanged config hit the cache
   (assert via cache-size introspection: size stays 1, or a hit counter).
2. Config change invalidates within TTL (or immediately if the reload hook
   is reachable).
3. All existing model-routing tests pass unchanged (semantics identical,
   cache is additive).
