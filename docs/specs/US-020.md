# US-020 — Interactive run dashboard in TUI

## Status

planned

## Lane / Priority

normal · P2

## Source

- `docs/stories/backlog.md` — DX epic, US-020 (planned).

## Problem

`src/ui/run-dashboard.ts` (`RunDashboard implements DashboardComponent`,
`render(columns)`) is a passive, re-rendered pane. There is no interaction:
you cannot select a run/task, open its transcript, request detail, or cancel
— all of that requires typing team-tool commands.

## Goals / Non-goals

- Make the dashboard interactive: select a row, open the selected run's task
  view / transcript, trigger cancel/export for the selection.
- Reuse existing renderers (dashboard panes, transcript viewer, overlay) —
  no new visual language.
- NOT in scope: mouse support; a new full-screen app (the dashboard stays a
  pane inside pi's TUI).

## Design

Anchors: `src/ui/run-dashboard.ts:487` (`RunDashboard`), the pane renderers
in `src/ui/dashboard-panes/`, the keybinding registry in
`src/ui/keybinding-map.ts`, and the surface/overlay wiring (panes are hosted
by the crew widget/TUI host — see `src/ui/widget/index.ts`).

Proposal:

1. Add a selection cursor: `selectedIndex`, `moveSelection(delta)`; the
   rendered row marks the selection (reuse the existing focus marker
   `FOCUS_MARKER`).
2. Keybindings (registered in `keybinding-map.ts`, overridable like
   `keybinding-map-override.test.ts` covers): `j/k` (or ↑/↓) move,
   `enter` opens the selected run (dispatch to the existing run detail /
   transcript overlay), `x` → cancel confirm, `e` → export.
3. Actions delegate to existing handlers: cancel = the same path the
   dashboard's `runCancelFn`/`handleTeamTool({action:'cancel'})` uses; export
   = the existing export action (US-022 verify-close).
4. Rendering must stay cheap: reuse the existing precomputed frame +
   `snapshotCache` (dashboard already avoids fs on the hot path — preserve).

## Acceptance Criteria

1. Selection moves with j/k and wraps; the selection is visible in the
   render.
2. `enter` on a run opens its detail view; escaping returns to the dashboard
   with selection preserved.
3. `x` refuses to cancel a non-running run (no-op + status line);
   `x` on running opens a confirm; confirm dispatches the existing cancel.
4. No render-path regression: the dashboard still renders from the
   precomputed frame (no new fs reads on tick — assert via existing
   render-snapshot parity test or a spy).
5. Keybindings are overridable (same mechanism as existing overrides).
