# DP-02 — Dist slim (minify + drop map/build-meta from git)

## Status

planned

## Lane / Priority

normal · P1 (cheap, measurable, unblocks CI/boot)

## Source

- `docs/stories/backlog.md` — "Deferred — performance deep-dive 2026-09-18".
- Measured 2026-09-22: `dist/index.mjs` = **3,441,968 B** (3.44 MB / 3.5 MB
  budget = 98.4%); `dist/index.mjs.map` ≈ **8.3 MB** and
  `dist/build-meta.json` ≈ **785 KB** committed to git (dist git footprint
  ≈ **12.3 MB**). Worker boot ≈ 2.5 s, of which ~55% is bundle load (per the
  2026-09-18 b7 bench).

## Problem

`scripts/build-bundle.mjs:54` sets `sourcemap: true` and does NOT set
`minify`. Consequences:

1. The shipped bundle is near its 3.5 MB budget — the next feature breaks it.
2. Every worker spawn pays the un-minified parse cost (55% of a 2.5 s boot).
3. Git carries ~9 MB of artifacts (map + build-meta) that nobody consumes
   from the repo — they are debug/release metadata.

## Goals / Non-goals

- Enable `minify: true` in the esbuild bundle build (≈30–40% size reduction
  expected; verify, don't assume).
- Stop tracking `dist/index.mjs.map` and `dist/build-meta.json` in git
  (`.gitignore`), publishing them only in the GitHub Release (the release
  workflow already attaches dist artifacts — confirm).
- KEEP `dist/index.mjs` tracked (the extension loads it by default; see the
  bundle cold-start note in `.crew/knowledge.md`).
- NOT in scope: splitting the bundle, lazy-loading (that's a bigger design).

## Design

Anchors: `scripts/build-bundle.mjs:33-60` (esbuild options),
`.gitignore`, `.github/workflows/` (release asset upload),
`index.bundle.ts` (entry), and the loader in the repo-root `index.ts`
(bundle-first resolution).

Steps:

1. `build-bundle.mjs`: `minify: true`, `sourcemap: false` (drop map
   generation entirely — regenerating on demand is possible from source).
2. `.gitignore`: add `dist/index.mjs.map`, `dist/build-meta.json`.
   `git rm --cached` them (keep working copies).
3. Release workflow: attach the map (rebuilt with `sourcemap: true` in a
   release-only build) — or drop maps from releases too if nobody uses them.
   Decide in the PR; document the choice.
4. Verify: rebuild, record new size + md5, run `test:bundle`.

## Acceptance Criteria

1. New bundle size measured and recorded (target: < 2.5 MB; report actual).
2. `npm run test:bundle` + `test:critical` green with the minified bundle.
3. Fresh-clone `npm install` still works (the loader tolerates a minified
   bundle — no name-dependent logic).
4. Worker boot time re-measured (before/after) and recorded; expect
   improvement proportional to load share.
5. `git ls-files dist | wc -l` reduced as specified; repo `.git` size
   noticeably smaller.

## Validation

| Layer | Check | Expected |
|-------|-------|----------|
| Build | `npm run build:bundle` | success, smaller output |
| Bundle test | `npm run test:bundle` | 2/2 |
| Critical | `npm run test:critical` | 116/116 |
| Live | one real `team action=run` with the minified bundle | run completes (proves loader) |
| Git | `git ls-files dist` | no map/build-meta |

## Notes

- Coordinate with the knowledge-base note: after source commits the bundle
  must be rebuilt (`npm run build:bundle`) for live sessions to pick changes
  up — unchanged by this spec.
- If minification breaks `index.ts`'s bundle detection (e.g. it greps for a
  marker string), pin that marker with esbuild `banner`/`footer`.
