# US-030 — Webhook notifications on run completion

## Status

done (2026-09-23) — implemented + security-reviewed (MERGE-WITH-FIXES applied)

### Security review outcome (adversarial pass, required by spec)

The reviewer found the guard design sound (fail-closed creation, secret never
leaves HMAC, sensitive-config enforcement verified through the sanitize→merge
chain) but caught one HIGH + one MEDIUM that were fixed before commit:

- **HIGH — redirect bypass (fixed)**: fetch defaults to redirect:"follow" —
  undici chases up to 20 hops WITHOUT re-running the SSRF guard (302 →
  169.254.169.254 blind GET; 307 REPLAYS the HMAC-signed body to internal
  RFC1918). Fix: `redirect:"manual"` + any 3xx = permanent delivery failure
  (no retry); unit test pins the init contract (a stub cannot simulate undici's
  chasing — the contract assertion is the honest unit-level proof).
- **MEDIUM — hostname gaps (fixed)**: trailing-dot `localhost.` now stripped;
  URLs with userinfo refused outright (credentials must never sit in URLs).
- **LOWs (all fixed)**: goal first line capped at 256 chars (agent-composable
  stuffing channel); response body cancelled on both paths (socket pinning);
  logs + failure records carry URL ORIGIN only; pattern-valid-but-clock-invalid
  quietHours ("99:99-00:00") no longer silently kills every delivery;
  `team-settings get` now redacts sensitive-marked values (***, incl.
  webhook.secret and the pre-existing otlp.headers class) and
  notifications.webhook.* joined KNOWN_KEYS.
- **Documented limitations (not fixed, by design)**: hostname-literal guard —
  no DNS resolution, so a DNS name that RESOLVES to loopback (nip.io, rebinding)
  passes; RFC1918 is deliberately allowed (internal webhooks are a use case).
  Replay protection is receiver-side (timestamp/nonce not in the signature).

Deviations from spec text (deliberate): failure event named `crew.webhook.failed`
(pi-events naming convention); webhook config block schema-marked 🔒 sensitive
(user-config-only — an untrusted repo cannot set an exfil URL or bypass the
guard); 4xx = fail-fast without retry; `cost` rounded to 6 decimals.

## Problem

Notifications today are local only: `NotificationRouter`
(`src/extension/notification-router.ts:70`, with quiet-hours
`isInQuietHours`/`parseHHMMRange`) routes to the TUI/terminal. Nothing
leaves the machine, so unattended/long runs (goal loops, scheduled jobs)
cannot notify an external system.

## Goals / Non-goals

- On run terminal status (`completed`/`failed`/`cancelled` — the same
  transitions the schedule toast bridge observes), POST a JSON payload to a
  configured webhook URL.
- Respect existing config surface: add `notifications.webhook` config,
  honoring the existing quiet-hours gate.
- Safety first: no new runtime dependency (Node 22 has global `fetch`);
  opt-in only (no default URL); PII-safe payload (runId, status, team, goal
  first line, cost — NO transcript/events by default).
- NOT in scope: inbound webhooks, retries beyond a single bounded retry,
  GitHub-specific formatting (that's US-031).

## Design

Anchors: `src/extension/notification-router.ts` (extend), the run-terminal
transition observation point (the schedule toast bridge
`src/extension/registration/schedule-toast-bridge.ts` shows the event shape;
run-terminal events also flow through `pi.events`), `src/config/types.ts`
(config additions).

Payload:

```json
{ "event": "run.terminal", "runId": "…", "status": "completed",
  "team": "implementation", "goal": "first line…", "durationMs": 12345,
  "cost": 0.0123, "tokens": 22000, "at": "ISO" }
```

Delivery:

1. Config `notifications.webhook = { url, enabled, secret? }`.
2. On terminal transition: if enabled and not in quiet hours → POST with
   `content-type: application/json`; if `secret`, set
   `x-pi-crew-signature: sha256=<hmac(payload, secret)>`.
3. Timeout (e.g. 5 s) + ONE retry on 5xx/network error; failures logged
   via `logInternalError` and surfaced as a `webhook.failed` event — never
   block the run lifecycle path (fire-and-forget, like other notification
   sinks).
4. SSRF guard: refuse non-http(s), refuse localhost/link-local unless an
   explicit `allowLocalhost: true` is set (documented).

## Acceptance Criteria

1. Disabled by default; zero network calls when unset (assert with a
   stubbed fetch in tests).
2. Enabled + terminal transition → exactly one POST with the documented
   shape; quiet hours suppress it.
3. Webhook failure never throws into the run path (test: fetch rejects →
   run still completes, error logged, one retry attempted).
4. HMAC signature verifiable when `secret` set (test with a known key).
5. SSRF guard blocks `file://`, `http://169.254.x`, `http://localhost`
   without the opt-in.
