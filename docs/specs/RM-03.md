## Problem

Four review notes are comment/doc-only gaps — each is a place where the code
relies on an invariant that is NOT written down, so a future editor can
break it without noticing:

| # | Note | Where |
|---|------|-------|
| 3 | Terminal durable-fsync behavior in the coalesced write path is undocumented | `src/state/atomic-write.ts` (coalesced flush) |
| 4 | `lastWrittenStatus` single-writer assumption undocumented | manifest writer path (`src/state/stores/state-store.ts`) |
| 6 | Sweep-before-cap ordering assumption undocumented | connection/registry cap sweep |
| 7 | Semaphore "dead comment" (a comment referring to removed code) | semaphore module |

## Design

Documentation + comment only — no behavior change:

1. Each note gets an explicit comment stating the invariant, WHO relies on
   it, and what breaks if violated. Prefer the `// INVARIANT (single-writer):
   …` style so it is greppable.
2. For #7, delete the stale comment (or rewrite it to describe the current
   code).
3. Add a `docs/decisions/` or `docs/` note ONLY if an invariant is
   cross-module (single-writer `lastWrittenStatus` qualifies); otherwise an
   in-code comment is the right home.

## Acceptance Criteria

1. All four anchors carry an explicit invariant/explanation comment (or the
   stale comment is removed).
2. No code behavior change — the diff is comments/docs only (verifiable by
   `git diff --stat` + a test run showing identical results).
3. Grep for the invariant markers returns the four sites.
