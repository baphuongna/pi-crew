## Execution model

- **5 batches, each independently shippable + independently verifiable.** Batches sequence the
  work by risk/dependency and mark each *release-ready* when its gate passes. **Do NOT bump the
  version or publish** — that is decided by you, at whatever boundary you choose (one release
  after all batches, or a cut after any single batch).
- **Within a batch**, work items are sequenced by dependency; parallelizable items are marked `∥`.
- **Every work item** ends with: changed files, new tests, risk, rollback. An engineer must be
  able to execute an item without re-investigation (all line refs verified first-hand).
- **Reuse existing primitives** wherever they already exist (listed in [Appendix A](#appendix-a--reusable-primitives)).
- **No behavior change** is allowed on the happy path without a characterization test first.

## Risk legend

- 🟢 low — isolated, pure-algorithm or read-path, has a clean test seam
- 🟡 medium — touches persistence/locking; needs crash-recovery + durability tests
- 🔴 high — touches the event log or broker protocol; needs integration + kill-9 tests

# Batch 1 — main-thread stalls + cheap wins

**Goal:** eliminate the two multi-second-to-multi-minute main-thread blocks + the per-event
full-log rewrite, plus three one-line wins. Expected: no more heartbeat-stale misclassification
under load.

> Ordering: **W1-1 → W1-2 → (∥ W1-3, W1-4, W1-5)**. W1-1 and W1-2 are the headline fixes; the
> rest are independent and can be done in parallel after.

## W1-1 · Segment-ring `BoundedTail` (P0-1) — 🟢

**Root cause (verified):** `src/runtime/child-pi-kill.ts:68` `appendBoundedTail` builds
`new TailCaptureStage(...).apply(current + chunk)` per call. `apply()` (`compact-stages/tail-capture-stage.ts:60-67`)
runs `Buffer.byteLength(text)` over the whole ≤512 KB buffer every stdout line, plus an O(n)
`while(...) tail = tail.slice(0,-1)` loop for multi-byte output. Call sites: `child-pi.ts:603`
(stdout/line), `:916` (stderr/chunk).

**Fix:**
1. New `src/runtime/compact-stages/bounded-tail.ts` — a segment ring with a running byte counter:
   ```ts
   export class BoundedTail {
       #segs: string[] = []; #bytes = 0; #dropped = false;
       constructor(private readonly maxBytes = MAX_CAPTURE_BYTES) {}
       push(chunk: string): void { /* push; while #bytes>max && #segs>1 shift+subtract */ }
       value(): string { /* join; optional marker; byte-exact boundary trim ONCE */ }
   }
   ```
   `value()` does the byte-precise trim with `Buffer.from(seg).subarray(-n)` + a ≤3-byte UTF-8
   boundary scan — **once**, not per char.
2. `child-pi.ts`: replace the `let stdout = ""` / `let stderr = ""` accumulators with
   `new BoundedTail()` instances; `stdout = appendBoundedTail(...)` → `stdoutTail.push(\`${line}\n\`)`,
   read `value()` only at result-build time.
3. Keep `appendBoundedTail()` as a thin deprecated wrapper (maps to a one-shot BoundedTail) for
   any external caller — grep confirms only `child-pi.ts` uses it.

**Tests:**
- `test/bench/bounded-tail.bench.ts`: 5,000 CJK lines (200 chars each) must complete `< 50 ms`.
  Wire into `npm run bench:check` (15 % regression threshold).
- `test/unit/bounded-tail.test.ts`: byte-exact cap correctness (ASCII + CJK + emoji boundary),
  marker appears iff bytes dropped, `value()` idempotent.

**Changed files:** `+ src/runtime/compact-stages/bounded-tail.ts`, `src/runtime/child-pi.ts`,
`src/runtime/child-pi-kill.ts` (deprecate wrapper), `+ test/unit/bounded-tail.test.ts`,
`+ test/bench/bounded-tail.bench.ts`, `package.json` (bench script wiring).

**Risk 🟢:** isolated to output capture; existing child-pi output tests + the new bench are the
gate. No persistence/locking touched.

## W1-2 · Per-path rotation counter on all append paths (P0-2) — 🟢

**Root cause (verified):** `src/state/event-log.ts` — `let appendCounter = 0;` (line 72) is a
single module-global; `appendCounter++` exists at **only one** place (line 1103, sync path). The
async path (line 767) checks `appendCounter % 100 === 0` but never increments → `0 % 100 === 0`
is **always true** → `needsRotation()` runs on **every async append**, and once over 4 MB,
`prepareCompaction()` does a full read+parse+rewrite **per event**.

**Fix:**
```ts
const appendCounters = new Map<string, number>();
function tickAppendCounter(eventsPath: string): boolean {
    const next = (appendCounters.get(eventsPath) ?? 0) + 1;
    appendCounters.set(eventsPath, next);
    return next % 100 === 0;
}
```
Call `tickAppendCounter(eventsPath)` from **all three** append paths (async `doAppendUnderLock`,
sync `appendEventInsideLock`, `appendEventBatchInsideLock`) and replace the inline
`appendCounter % 100 === 0` checks. Bound the map: delete the entry when a run finalizes
(cleanup hook in `lifecycle-handlers.ts` closeout), or cap at e.g. 256 with FIFO eviction.

**Tests:**
- `test/unit/event-log-rotation-counter.test.ts`: append 250 events via `appendEventAsync` to a
  stubbed path with `needsRotation` spied → assert consulted **exactly 2×** (at 100 and 200), not
  250×. Repeat for the sync + batch paths. Assert per-path independence (two paths tick independently).

**Changed files:** `src/state/event-log.ts`, `+ test/unit/event-log-rotation-counter.test.ts`.

**Risk 🟢:** the rotation *frequency* changes (1×/100 appends instead of every append) — strictly
less work, same compaction semantics. Characterize current behavior first if any test asserts
today's (buggy) cadence.

## W1-3 · `Promise.all` for `before_task_start` hooks (P1-10) — 🟢  ∥

`for (const task of readyBatch) { const taskReport = await executeHook("before_task_start", ...); ... }`
runs N hooks sequentially on the pre-spawn critical path.

**Fix:**
```ts
const reports = await Promise.all(
    readyBatch.map((task) => executeHook("before_task_start", { runId, taskId: task.id, cwd }).then((r) => [task, r] as const)),

for (const [task, taskReport] of reports) { /* apply skip mutations as today */ }
```
Keep the post-resolution mutation loop sequential (it mutates `ctx.tasks`/`ctx.manifest`); only
the hook *invocations* parallelize. **Also** convert the other sequential-append loops the
verifier confirmed (`:1062-1069` cancel, `:1916-1930` fairShare) to `Promise.all`, and the
informational `:1254-1268` + `advanceWorkflowPhases` appends to `appendEventBuffered`.

**Tests:**

  register N slow hooks (each `sleep(50)`), assert total wall-time ≈ 50 ms (not N×50), and assert

**Changed files:** `src/runtime/team-runner.ts`, `+ test/unit/before-task-start-parallel.test.ts`.

**Risk 🟢:** hooks must be side-effect-independent (they are — each returns a report; the audit
confirms the post-resolution mutation is what matters). If a user hook writes to shared state,
order changes — document in CHANGELOG.

## W1-4 · Feed global cap into scheduler concurrency (P1-7) — 🟢  ∥

**Root cause (verified):** `src/runtime/concurrency.ts:48` —
`Math.min(requested, hardCap)` never consults `getWorkerCapCapacity()`. On a 4-core machine the
scheduler dispatches 4 while the global semaphore holds 2 → 2 worktrees built + 2 agents marked
`running` with heartbeats for tasks that merely queue.

**Fix:**
```ts
const maxConcurrent = input.allowUnboundedConcurrency
    ? requested
    : Math.min(requested, hardCap, getWorkerCapCapacity());
```
(Import `getWorkerCapCapacity` from `global-worker-cap.ts`.) **Separately**, in
`src/runtime/semaphore.ts` replace the `MAX_QUEUE` `throw` with a rejected `Promise` carrying a
typed `SemaphoreFullError` (so callers can backpressure instead of crashing).

**Tests:**
- `test/unit/resolve-batch-concurrency.test.ts`: with `PI_CREW_MAX_WORKERS=2` and a workflow
  requesting 4, assert the decision is `2`. Keep `allowUnboundedConcurrency:true` bypass.

**Changed files:** `src/runtime/concurrency.ts`, `src/runtime/semaphore.ts`,
`+ test/unit/resolve-batch-concurrency.test.ts`.

**Risk 🟢:** strictly reduces over-dispatch; the global cap was already the binding constraint, so
behavior under load improves, regresses nowhere.

## W2-1 · Async agents lock + coalesced in-loop saves (P0-3) — 🔴

**Root cause (verified):** `crew-agent-records.ts:108` `withAgentsLock` uses `sleepSync`
(`Atomics.wait`, blocks the main thread) in a `while(true)` with a 60 s deadline. All 9
`team-runner.ts` call sites (928,1135,1301,1307,2156,2315,2335,2353,2358 — **2358 is in the main
per-batch loop**) call the **sync** `saveCrewAgents`.

**Fix:**
1. New `withAgentsLockAsync` using the existing `workspace-lock.ts` (`sleepOrAbort`,
   `DEFAULT_LOCK_POLL_MS`) — O_EXCL acquire, async `sleep` between attempts, same stale-reap logic.
2. New `saveCrewAgentsAsync` wrapping `atomicWriteJsonAsync` under `withAgentsLockAsync`.
3. Migrate the **in-loop, non-terminal** call sites (`:2315, :2335, :2353, :2358`) to
   **`saveCrewAgentsCoalesced`** (already exists at `:352`, `AGENT_COALESCE_MS=250`, best-effort,
   no lock) — these are progress updates, not terminal state, so best-effort is correct.
4. Migrate the **terminal/closeout** sites (`:928, :1135, :1301, :1307, :2156`) to
   `saveCrewAgentsAsync` (full durability, async lock, no main-thread block).
5. Keep the sync `saveCrewAgents` **only** for `process.on("exit")`-class handlers; add a
   `// SYNC-OK: exit handler` comment + the `no-sleepSync` lint rule from [CI gates](#new-ci-gates).

**Tests:**
- `test/unit/agents-lock-async.test.ts`: N concurrent `saveCrewAgentsAsync` under contention —
  assert no `sleepSync` called (spy), all writes serialize correctly, total time ≈ work not N×250 ms.
- Crash-recovery integration test: kill -9 mid-batch → `agents.json` consistent (coalesced flush
  on the in-loop path is best-effort; terminal flush is durable — assert terminal state survives).

**Changed files:** `src/runtime/crew-agent-records.ts`, `src/runtime/team-runner.ts` (9 sites),
`src/runtime/workspace-lock.ts` (if reuse needs export tweak), `+ test/unit/agents-lock-async.test.ts`.

**Risk 🔴:** locking + durability. The coalesced path is best-effort by design (audit confirms
`saveCrewAgentsCoalesced` is *already written* for exactly this). Terminal state must stay durable.
Rollback: revert to sync variant (the coalesced helper is additive).

## W2-2 · Reduce fsyncs per event (P0-4) — 🟡

**Root cause (verified):** async append path does 5 fsyncs/event: pid file (2, sync
`atomicWriteFile`), log `fd.sync()` unconditional (1), `.seq` sidecar (2, sync `atomicWriteFile`).
The sync path already implements F3a (skip data fsync for non-terminal, `event-log.ts:~1064`); the
async path fsyncs unconditionally (`:743`). The pid + seq writes are the **synchronous** variant
inside an async path (blocks the loop).

**Fix:**
1. Pid file → `atomicWriteFile(pidFile, ..., { durability: "best-effort" })` (disposable; stale-lock
   reaper handles loss). −2 fsyncs.
2. Async path mirrors F3a: `if (TERMINAL_EVENT_TYPES.has(fullEvent.type)) await fd.sync();` (both
   the worker and non-worker branches). −1 fsync on non-terminal events (the common case).
3. `.seq` sidecar → best-effort, or only on terminal events. `event-reconstructor.ts` already
   tolerates an inconsistent tail (documented at `event-log.ts:1065-1071`). −2 fsyncs.

**Tests:**
- `test/unit/event-append-fsync.test.ts`: spy `fs.fsyncSync`/`fd.sync`; assert a non-terminal
  event does ≤1 fsync (seq best-effort + no data fsync); a terminal event does the full set.
- **kill -9 durability integration test** (new, in `test/integration/`): append N events, kill -9,
  restart, assert event-reconstructor recovers a consistent tail and no duplicate seqs. This is
  the regression guard for relaxing durability.

**Changed files:** `src/state/event-log.ts` (async path ~500-770), `+ test/unit/event-append-fsync.test.ts`,
`+ test/integration/event-log-durability.test.ts`.

**Risk 🟡:** deliberately relaxing durability on non-terminal events. The sync path already does
this safely (F3a shipped, event-reconstructor handles it). The kill-9 test is mandatory.

## W2-3 · Memoize validated agent path per task + batch agent-event appends (P1-5) — 🟡

3. Keep `seq` purely in memory (`agentEventSeqCache` already exists); flush the `.seq` sidecar

4. Batch `events.jsonl` appends behind a 50 ms timer using the same mechanism `child-pi-transcript.ts:37`

**Changed files:** `src/runtime/crew-agent-records.ts`, `src/runtime/child-pi-transcript.ts`,

## W2-4 · Redact once at the boundary + cheap pre-filter (P1-6) — 🟡

**Root cause (verified):** `redactSecretString` (`redaction.ts:236`) does ~14 full-string passes
per call (split + PEM + authHeader + bearerTokens + 6 regex + inlineSecrets, incl. toLowerCase/
toUpperCase + char loops). The same payload is redacted at **4 sinks**: transcript
(`child-pi-transcript.ts:91`), agent events.jsonl (`crew-agent-records.ts:471`), agent output.log
(`:558`), run events.jsonl (`event-log.ts:723/1063`).

**Fix:**
1. Redact **once**, at `ChildPiLineObserver.emitLine` (`child-pi-streams.ts`) where the event is
   first materialized; cache the redacted string on the event object; have all four sinks consume
   the cached value (the sinks currently each call `redactSecrets`/`redactSecretString` — drop those).
2. Add a cheap pre-filter in `redactSecretString`: bail to the input unchanged unless it contains
   one of `-----BEGIN`, `eyJ`, `gh`, `AKIA`, `xox`, `AIza`, `sk_live_`, `Bearer`, `=`, `:`. The
   ~99 % clean case then costs one sweep.
3. Rewrite `redactBearerTokens`/`redactInlineSecrets` to slice spans instead of pushing per char
   (the audit's note; `redactInlineSecrets` is already O(n) per its comment — verify bearerTokens).

**Tests:**
- Existing `redaction-redos-regression.test.ts` must pass. New
  `test/unit/redaction-once.test.ts`: emit one assistant message through the observer; assert
  `redactSecretString` is invoked **once** total across the 4 sinks (spy), and the clean-case
  pre-filter short-circuits (assert no allocation for a string without any marker).

**Changed files:** `src/utils/redaction.ts`, `src/runtime/child-pi-streams.ts`,
`src/runtime/child-pi-transcript.ts`, `src/runtime/crew-agent-records.ts`, `src/state/event-log.ts`,

**Risk 🟡:** redaction correctness is security-critical — the pre-filter must not let a real secret

## W3-2 · `listActive` filters `list`; per-entry TTL + real LRU; lazy top-N (P1-9) — 🟢

**Root cause (verified):** `manifest-cache.ts` — `list()` (237) and `listActive()` (312) each do a
full `roots.flatMap(collectRoots)` + per-run `parseManifestIfChanged`; `DEFAULT_TTL_MS=500`.
`SharedScanCache` (`scan-cache.ts`) evicts FIFO, TTL set once at bucket creation, `maxEntries=100`
thrashes against 84 runs. `collectRuns` reads all manifests even when only top-N is needed.

**Fix:**
1. `listActive()` filters the `list()` result (active = `status in {running,...}`) instead of
   re-scanning.
2. `SharedScanCache`: per-entry `expireAtMs` (refresh on access) + access-order LRU; raise
   `maxEntries` above the run count (e.g. 512).
3. `parseManifestIfChanged`: short-circuit `validateManifestForRoot`'s path checks when
   `mtimeMs`+`size` are unchanged (path validity can't change if the file didn't).
4. `collectRuns`: sort+slicse on `Dirent` names, read manifests lazily for the top-N only.

**Tests:** `test/unit/scan-cache-lru.test.ts` (access-order eviction); `test/unit/manifest-cache-listactive.test.ts`
(listActive doesn't re-scan — spy `parseManifestIfChanged`).

## W3-3 · Hoist git prune/list to per-run; per-repo worktree mutex (P1-11) — 🟡

**Root cause (verified):** `worktree-manager.ts` runs `git worktree list --porcelain` (848,
uncached) and `git worktree prune` (924, writes the repo) **per task**; N tasks race them with no
mutex. Reuse path deliberately invalidates `_cleanLeaderCache` (919) then re-runs `git status` (920).
`clearGitRootCache`/`clearCleanLeaderCache` are dead code.

**Fix:**
1. Hoist `worktree list --porcelain` and `worktree prune` to **once per run** (call before the
   batch dispatch in `team-runner.ts`, pass the result into `prepareTaskWorkspaceAsync`).
2. Add a per-`repoRoot` async mutex (`Map<repoRoot, Promise>`) around the `worktree add` critical
   section.
3. Reuse path: memoize the `status --porcelain` instead of delete-then-recheck.
4. Delete `clearGitRootCache`/`clearCleanLeaderCache` (zero callers — W5-1 overlaps).

**Tests:** `test/unit/worktree-per-run.test.ts` (spy `gitAsync`; assert `worktree prune` runs once
per run, not per task); `test/unit/worktree-mutex.test.ts` (concurrent dispatch serializes the add).

## W3-4 · Cache manifest on the broker connection; replace 200 ms poll (P1-12) — 🟡

**Root cause (verified):** `crew-broker.ts` calls `loadRunManifestById` at 6+ sites (764,833,877,
925,1039,1110); `loadRunManifestById` does the containment check + 2 stats **before** its own
cache, so a cache hit still costs ~10 syscalls. `handleTaskWaitStatus` polls every 200 ms for ≤60 s.
`locateRunCwd` + `handleStatus` double-loads.

**Fix:**
1. Cache `{manifest, eventsPath}` on `ServerConnection` after `hello` (runId is fixed for the
   connection's life); invalidate via the existing `runEventBus` generation counter.
2. Memoize `resolveRunStateRoot(cwd, runId)` in a TTL map (containment verdict can't change unless
   the dir is replaced).
3. Replace the 200 ms `task.waitStatus` poll with a `runEventBus` subscription on `task.status`
   (emit-driven, with a deadline fallback).
4. `readMailbox` gets an `{offset, limit}` parameter (stop reading the whole file per page).
5. `locateRunCwd`: memo `runId → cwd` after first hit; `handleStatus` reuses the located cwd
   instead of re-calling `loadRunManifestById`.

**Tests:** `test/unit/broker-connection-cache.test.ts` (loadRunManifestById called once per
connection, not per message); `test/unit/task-wait-status-event.test.ts` (resolves on event, not poll).

**Batch 3 gate (release-ready when):** full suite + a 84-run `.crew` fixture proving `list()` is fast.

# Batch 4 — startup + bundle — 🟢/🟡

## W4-1 · Delete (or fix) `startRuntimeWarmup` (P2-14) — 🟢  **decide first**

**Root cause (verified):** `runtime-warmup.ts:90` does `import(new URL(spec, import.meta.url).href)`.
In bundle mode (default), `dist/` has only `index.mjs`+`.map`+`build-meta.json` — **no `.ts`** —
so every spec resolves to `<pkg>/dist/*.ts` → ENOENT → swallowed → `getRuntimeWarmupStatus()`
falsely reports `completed:true`. The documented cold-start-race guard gates every subagent spawn
and provides **zero** protection. (The hot modules are already bundled — line 30497 — so warmup is
redundant even if fixed.)

**Decision:** **delete it** (preferred — it's redundant in bundle mode and broken by construction)
OR replace `new URL(spec, import.meta.url).href` with a bare `import(spec)` resolvable at bundle
time. If deleting, remove `awaitRuntimeWarmup()` call sites and document that the race is now
covered by lazy module loading instead.

**Tests:** if deleted, remove the warmup tests + assert no `getRuntimeWarmupStatus` references. If
